# Intake → project description → outcome

0. Establish the project owner, expected useful outcome, permitted material and disclosure boundary. Keep private raw conversations outside this starter.
1. Use `farshmaster/` for a bounded two-pass intake, or extract manually: candidate goals, decisions, requirements, unknowns and conflicts from permitted sources. Give each claim a source ID and a status. An AI paraphrase is not an owner decision.
2. Check completeness against the intended outcome and conflicts against original sources and authority. Ask the owner only about unknowns affecting the next consequential step.
3. Standard route: review extraction, then derive a specification with goal, requirements and acceptance criteria; obtain owner acceptance before treating it as binding.
4. Complex route: isolate author intent without technology choices, then evolve a conceptual Project Book with accepted decisions, open concepts, amendment procedure and derived artefacts. Preserve envisioned-but-unimplemented concepts without calling them delivered.
5. Before consequential action check actor, object, operation, authority, fresh preconditions and stop rule. Hold dependent work on missing authority. Define outcome criteria before work; after work check a separate real observation, not merely the executor's report.
6. When a source changes, review affected claims and decisions. An observation can support a proposal to amend the Book but cannot itself rewrite author intent.
